# План доработок Noda — 28.07.2026

Источник: голосовая постановка Тимы + три скриншота с телефона (IMG_8225–8227) и скрин ПК
(`.impeccable/pc-sync.png`). Ниже — расшифровка каждого пункта, что именно не так, что делаем.

Порядок выбран так: сначала то, что доедет по OTA за минуты (телефон), потом ПК, потом то,
что требует нативной сборки (виджеты).

---

## 1. Нижняя панель меняет цвет между разделами

**Что не так.** В «Финансах» и «Передаче» таб-бар тёмный, в «Заметках»/«Помощнике»/«ПК» — светлый.
Причина: `NativeTabs` в iOS 26 берёт scroll-edge appearance от контента под панелью; на экранах,
где ScrollView не доскроллен до края, включается «прозрачный» вид и стекло темнеет от подложки.

**Делаем.** Жёстко фиксируем непрозрачный светлый фон панели на всех экранах
(`backgroundColor` + `disableTransparentOnScrollEdge` + одинаковый нижний inset у всех ScrollView,
чтобы контент везде уходил под панель одинаково).

## 2. Иконка приложения — логотип мелкий

**Что не так.** `scripts/build_noda_logo.py` кладёт знак на 64 % холста, плюс у самого PNG-знака
есть собственные поля → визуально знак ~50 % иконки, вокруг много пустого фона.

**Делаем.** Обрезаем прозрачные поля источника по bbox, кладём знак на ~78 % холста,
перегенерируем: `assets/images/icon.png`, `app-icon-1024.png`, `android-icon-foreground/monochrome`,
`favicon.png`, `pc-app/icon.png|ico`, арт установщика. Проверяем на светлом и тёмном фоне.

## 3. Финансы: кнопки «+» и «Каршеринг» — не там, где нужно

**Что не так.** Кнопки в правом верхнем углу — тянуться далеко, а каршеринг Тима вносит по
несколько раз в день (90 % трат).

**Делаем.** Плавающая кнопка в **левом нижнем углу, над таб-баром**, привязана к экрану.
Тап → из самой кнопки анимацией (scale + fade из точки касания) разворачивается компактное меню:
«Каршеринг», «Новая запись». Тактильный отклик. Кнопка не перекрывает список (список получает
дополнительный нижний отступ).

## 4. Финансы: экран записи (скрин IMG_8226)

**Что не так.** Открывается лист на весь экран, где заполнено меньше трети; всё блёкло — серые
поля, ни одной иконки, дата в машинном формате `2026-07-25 12:56`, заголовок «Запись» без смысла.

**Делаем.**
- Компактный лист (`presentationDetents` — примерно на половину экрана, не на весь).
- Наверху — логотип мерчанта (`MerchantLogo`) и крупная сумма как главное поле.
- Дата/время — нативный `DateTimePicker`, а не текстовое поле.
- «Кто платил» — сегмент, «За что» — с подсказками частых значений (Каршеринг, Такси, Еда…).
- Живые цвета: акцент, цветной бейдж категории, иконка направления (мне должны / я должен).

## 5. Финансы: открытие существующей операции

**Что не так.** Тап по строке «1000 ₽» открывает тот же пустой полноэкранный лист.

**Делаем.** Тот же компактный лист из п.4 + шапка с логотипом, суммой и датой; действия
«Погашено», «Удалить» — прямо в листе. Свайп по строке в списке — быстрые действия
(погасить / удалить), как в Почте Apple.

## 6. Заметки: свайпы и «странное обновление»

**Что не так.** Редактор открывается как `Modal` поверх экрана, edge-swipe тянет его вручную и
на отпускании сохраняет через сеть — отсюда рывок, перерисовка списка и ощущение «страница
как-то обновляется». Плюс горизонтальный свайп конфликтует со свайпом удаления строки.

**Делаем.** Оптимистичное сохранение (список обновляем локально сразу, сеть — в фоне),
пружинная анимация закрытия без ожидания ответа сервера, разведение жестов
(`ReanimatedSwipeable` слева/справа vs edge-swipe), никакого ремоунта списка после закрытия.

## 7. Заметки: зазор над клавиатурой (скрин IMG_8225)

**Что не так.** Панель инструментов (Aa / чек-лист / таблица / AI / микрофон) висит примерно на
200 px выше клавиатуры. Причина — `KeyboardAvoidingView behavior="padding"` внутри `Modal`
с `presentationStyle="overFullScreen"`: он не знает про safe-area и добавляет её дважды.

**Делаем.** Убираем `KeyboardAvoidingView`, поднимаем панель по реальной высоте клавиатуры
(`keyboardWillShow` + `Keyboard.scheduleLayoutAnimation`) — тот же механизм, что уже работает
в помощнике.

## 8. Помощник: чаты только через меню

**Что не так.** Треды в API есть (`/ai/threads`), но на телефоне переключение спрятано в меню —
«нету разных чатов».

**Делаем.** Горизонтальный свайп между чатами (как переключение диалогов), выдвижная панель
со списком чатов слева, свайп по чату — удалить. Индикатор текущего чата.

## 9. Микрофон

**Что не так.** Кнопка-тумблер: нажал — пишет, нажал — стоп. Нет ощущения Telegram.

**Делаем.** Зажатие — запись; ведёшь влево — отмена (с подписью «сдвиньте для отмены»);
ведёшь вверх — фиксация записи «руки свободны»; волновая анимация уровня звука; таймер;
haptics на каждом состоянии. Общий компонент — используем и в помощнике, и в заметках.

## 10. Передача на телефоне (скрин IMG_8227)

**Что не так.**
- Лишний блок «Устройство / Выбери, где запустить команду» — и так понятно.
- Зависло на «Подключаюсь к серверу… Проверяю защищённое соединение», 0 %, и **«Остановить»
  не работает** — после этого ни отправить, ни забрать.

**Делаем.**
- Убираем подписи, оставляем компактный переключатель устройства.
- «Остановить» всегда разблокирует интерфейс локально (не ждёт ответа ПК).
- Watchdog: если фаза не менялась дольше 45 с — показываем «Похоже, зависло» и предлагаем
  повторить/остановить.
- Показываем «последняя синхронизация: когда, с какого устройства, в какую сторону».

## 11. Передача на ПК

**Что не так.**
- При входе в раздел сразу стартует какой-то процесс, назначение неочевидно.
- Непонятно, что нажимать при «изменения есть с обеих сторон».
- Нет истории: кто и когда отправлял последним.
- Передача падает на занятых файлах и обрывах.

**Делаем.**
- Автопроверку подписываем явно («Сверяю, что изменилось — 4 с») и даём отключить.
- Рекомендация действия текстом: что именно произойдёт по каждой кнопке и сколько файлов.
- Журнал последних операций (устройство, направление, время, число файлов) — на виду.
- Занятые файлы: определяем держащий процесс и предлагаем закрыть его одной кнопкой
  (с явным подтверждением — насильно убивать чужие процессы молча нельзя), затем автоповтор.
- Переподключение при обрыве SFTP уже есть в `pc-app/sync/` — проверяем, что попало в сборку.

## 12. Последние фото

**Что не так.** Выбор количества колесом «1 фото / 2 фото…» — не видно, что именно отправляешь.

**Делаем.** Лист с сеткой реальных превью последних 30 фото, мультивыбор тапом, счётчик
на кнопке отправки.

## 13. Иконки в стиле Apple

Генерируем локальным Codex (`codex exec`, фича image_generation — платные API запрещены)
паки иконок: разделы, категории финансов, сервисы каршеринга, действия. Выбираем лучшие,
уменьшаем до нужных размеров, подставляем в приложение, ПК и сайт.

## 14. Виджеты iOS

Цель: виджет на рабочем столе и на экране блокировки — тап добавляет каршеринг/заметку за секунду.
Технически это отдельный **WidgetKit-таргет** (Swift) — в Expo делается через
`@bacons/apple-targets` + App Group для общего хранилища + deep link `noda://…` в приложение.
Требует нативной пересборки (не доедет по OTA). Сначала — проверка совместимости с SDK 56,
затем реализация, затем сборка через GitHub Actions.

## Что нужно от Тимы

1. **Виджет.** Завести App Group `group.com.arratima.aura` на developer.apple.com и включить
   его у `com.arratima.aura` и `com.arratima.aura.ExpoWidgetsTarget`. Через API Apple это
   не делается (`/v1/appGroups` → 404). После этого вернуть блок `expo-widgets` в `app.json`
   и пересобрать.
2. **Релиз ПК-приложения.** Новый GitHub PAT со scope `repo` вместо протухшего `GITHUB_TOKEN`
   в `.env`. Пока установщик лежит локально: `pc-app/dist/Noda-Setup-1.18.0.exe`.
